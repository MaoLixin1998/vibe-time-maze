# Python / pygame项目补充

版本：0.8。日期：2026-10-10。基线：通用开发规范1.6.1。适用：本作Python源码、测试、检查工具与构建配置。正式游戏按三键七音/音区、单首原创时间曲与选定隐藏曲段设计，正式灰盒与检查器已建立；独立本机试听与正式包分别管理。区域文件隔离与灰盒延续规则已落实；本版同步实际拆分结构和自动检查覆盖。

## 1 选型和覆盖关系

Python由用户确定，pygame-ce为本轮2D俯视实现路线。pyproject.toml声明Python>=3.13，requirements.lock锁定pygame-ce==2.5.8；独立环境.venv-game实际验证Python 3.13.13。无图片处理需求不加入Pillow，不引入AppKit、PyObjC或桌宠原生启动器。

采用[pygame-ce官方文档](https://pyga.me/docs/)定义的事件、显示和生命周期接口，安装包名为pygame-ce，代码导入名为pygame。独立虚拟环境按[Python venv文档](https://docs.python.org/3.12/library/venv.html)建立；正式依赖离线复用已安装正规发行，网络源未验证成功；构建后端setuptools>=70在本机独立构建解释器中验证。框架接口名称保留真实契约，其余规则继续有效。

## 2 Python形式

| 对象 | 本作形式与边界 |
| --- | --- |
| 包、模块、函数、方法、变量 | 含义明确的snake_case；不覆盖内置名称 |
| 类 | PascalCase，一类一文件，包含数据类、异常和测试类 |
| 稳定常量 | 所属职责模块内UPPER_SNAKE_CASE；默认配置与实际状态分开 |
| 布尔值 | is_/has_/can_等表达明确判断；单位采用_seconds、_tiles、_pixels |
| 类型 | 公开参数与返回写类型；边界仍校验实际值，不把bool当int接受 |
| 注释 | #中文独立写在定义、装饰器和逻辑语句上方；多行有意义的参数/分支也说明 |
| 文档字符串 | 模块可有；接口工具确需时置于定义体首句，补充接口，不替代上方说明 |
| 格式 | UTF-8、末尾换行、4空格缩进、单行建议100字符；格式工具不能删掉必要说明 |

正式源码、测试和工具均适用。多行表达式不以闭合括号行凑注释；说明解释意图、单位、边界和状态变化，不用“执行代码”等占位语。自动工具只判断可靠的形式，语义人工审查。

### 3.1 区域文件隔离与共享机制（强制）

1. 按实际关卡／区域作为可独立制作和修改的内容单元。本作A—G每区必须有独立数据文件，保存本区地形、碰撞、门、交互物、领地、地标及专属资源引用；同一大JSON里的七个对象或同一文件里的七段分支不算完成文件隔离。`data/level.json`只承担区域清单、初始状态及必要全图配置，不继续承载七区完整布局。
2. 区域专属规则按需要归入`model/area_rules/`，区域专属绘制／动画按需要归入`rendering/areas/`，名称表达实际区域与职责。通用地形和物件绘制仍可共用；没有专属逻辑的区域不建立空类、空包或转发文件。一个类一个文件，不把场景专属业务和绘制合进万能区域类。
3. 移动、碰撞判定、三键输入、昼夜／年龄、开箱、共享机关、鸡行为及重试等真实共用机制继续在所属公共模块维护。区域通过数据、显式参数及公开接口使用它们，不复制七套近似实现，不在共用循环、GameSession或Renderer中持续堆积区域ID分支。跨区用例由会话协调，区域模块不读取或改写另一模块的私有状态。
4. 区域、门、物件及资源使用稳定ID；每个门连接只由其定义维护，区域清单不另抄一份通行条件。装载时组合完整地图，一起校验ID唯一、目标引用、条件、合法落脚与回程；分文件不改变单局共享状态及完整快照语义。GameSession调用区域规则并传入所需公开数据／能力，区域规则不反向导入GameSession。区域专属代码仍遵守纯模型无pygame／IO、渲染只读快照的原依赖边界。
5. 区域基础资源按所属区域或真实复用职责分类，正式资源引用显式声明并缓存；灰盒占位与正式素材经相同公开展示接口接入。替换美术不擅自改变门、路径、碰撞、年龄／昼夜条件或胜利规则；确需改变产品规则时，单独修改定义并验证。资源目录分类不等于Git或发行放行，仍逐项审阅分发权和准确允许集合。
6. 灰盒是正式游戏核心的可玩阶段，默认继续沿用正式模型、输入、地图接口及回归。主线不得写成只为验证或拍摄服务、换素材时还要另写一套的临时实现；独立试验明确另设入口和归属。基础图形可被正式角色／场景替换，但最终动作、运镜、操作空间、追逐公平性、提示、音效与完整试玩分别验收，不能把素材替换直接记为游戏完成。
7. 区域文件迁移前按R02展示现状与目标树；迁移同步装载器、跨区校验、资源定位、测试发现、精确Git／打包允许集合和文档。保留旧稿集中归档、保持唯一现行入口，禁止迁移后并列维护两份当前布局。回归使用与正式运行相同的组合地图，检查逐区装载、跨区主线、回程及失败恢复，并在无制作目录的安装副本验收。

当前实现：A—G每区独立JSON，level.json只存清单与全图配置；F／G专属入场规则在model/area_rules，G出口展开在rendering/areas，共用角色绘制保持公开独立接口。装载、精确Git／打包集合和整图校验已同步，拆分前后布局与规则保持一致。检查器覆盖清单／文件归属、完整资源集合、全图连接和构建声明；不自动判断所有区域ID分支的职责，是否重复通用机制与注释质量仍人工审阅。

## 4 状态与规则边界

GameSession是一次游戏的协调者，组合MazeState、Player、Timeline和ChickenFlock。model/keyboard_rules.py以纯函数校验(note_id, octave)事件：note_id为1—7、octave为0/1，拒绝bool和非法类型/范围；按已核定的原创主线及隐藏曲段解析结果，不读设备、音频、时间或文件。公开play_keyboard(note_events)协调正式效果，不暴露玩家昼夜直切。各对象通过公开能力协作，不建万能Manager/Utils/BaseGame，年龄差异用状态与数据，不建少年/成年继承树。

三键造型保持上方语音长键、下方左✓右×。音符1/2/3分别映射物理键1/2/3，4=键1＋2、5=键2＋3、6=键1＋3、7=全部；每个组合是一条笛子音色单音事件，不是和弦或钢琴。独立demo的Shift＋数字给高八度，正式输入沿用音符/音区模型。当前灰盒用Enter提交完整音符顺序及八度，不要求节奏；HUD图标/线索须使静音和无音律知识的玩家可玩。不增加真实麦克风、AI、真人音高识别或复杂音乐系统。

主线只用一首原创时间曲`time_shift`，effect=`toggle_day`，每次合法命中后切换当前昼夜；灰盒先用基础八度候选6-3-2-5-2-1，待实际试玩定谱，不保留单独切夜、切昼两首主线。B第一只谱箱收录时间曲，第二只谱箱收录塞尔达摇篮曲`egg_lullaby`彩蛋；均真实开箱取得、跨年龄昼夜保留。摇篮曲已核验为7-高2-6重复两遍，仅给可见回应；其余五首已选定隐藏曲段与具体效果继续待定。彩蛋不作为通关条件，不代替原创时间曲。

原创曲谱、前缀上限、提交规则、效果ID和线索从正式rules/text数据校验后注入；检查重复或有歧义的模式，合法未匹配/未完成不改世界。InputController独占有界前缀，不写死为三个；过滤按键自动重复，面板关闭、暂停、失焦、失败、重试和重开均清空，不跨状态补接。Application读取InputController.keyboard_snapshot()并传给Renderer.draw，渲染不持有/导入输入控制器或访问可变列表。正式面板聚焦时输入不移动，打开本身不暂停；暂停通过GameSession公开能力冻结。鸡叫P1保持稳定回应，不扩追逐AI或改写警戒。

最新隐藏彩蛋需求复用上述离散输入及纯规则；正式数据区分原创主线与选定隐藏曲段，跨类别重复、前缀歧义及提交结果一并校验。六首曲名已确定，其中摇篮曲列为B第二只谱箱内容；摇篮曲输入已核验，octave=1仅用于高2；只反馈不改世界，其余五首输入与回应仍须逐项核定。当前灰盒采用Enter提交、无节奏要求；隐藏项不作为通关依赖，任何状态效果仍遵循合法性和恢复规则。现有试听demo不因此增加匹配功能。

地图定义和配置注入后不被运行状态反写。可变嵌套结构独立归属；GameSnapshot只包含不可变值或独立副本，不向绘图泄露模型内部列表。稳定ID与显示文字分开，切换文字不改变规则。初始探索检查点在首次拔剑后保存；重试恢复完整业务状态，不保存乐器输入前缀，也不回滚会话事件序号。

位置单位为格，渲染单位为像素，时间增量为秒。移动采用网格规则与画面插值；插值不改变碰撞结果。切换年龄仅在剑台，键盘命中的昼夜效果在完整落脚格提交；先验证目标状态合法，再整体提交，失败保留原状态并给出原因。暂停/对话/失败/胜利时冻结相应模拟，焦点丢失清空按键与前缀，避免恢复后连续触发。

## 5 pygame适配与资源

单一应用循环收集事件、调用模型、消费结果事件、绘图；绘制不推进游戏。时间增量校验有限、非负，长卡顿采用受控子步与追赶上限，最大追赶0.25秒、子步0.05秒，实际行为由正式回归验证。资源在启动或显式切换时加载并缓存，不逐帧读盘。

Application拥有pygame显示、字体和音频的初始化与清理，退出用finally；普通导入没有GUI/IO副作用。音频设备不可用时在声音边界静音并保留原因，正式曲谱判定仍按离散音符事件完成，不依赖实际听音。必需地图或曲谱规则缺失/非法必须报错；默认字体策略须能在干净环境显示必要信息，不只依赖本机中文字体。

资源路径由包资源接口或入口显式提供，不依赖当前工作目录。增强美术通过显式参数加载，校验清单、尺寸、时长和路径，拒绝越界及符号链接逃逸；不自动搜索制作资料目录。删除整套本机制作目录后默认游戏仍能运行与通关。真实昼夜及鸡群结果调用正式play_keyboard；主体只处理离散音符，不包含外部演出时序或真人音频识别。

## 6 检查入口和实施要求

统一入口为`python -m support.tools.check_project`；本轮在写主体代码前建立并执行最小检查器：

- 工作区模式：语法、编码/换行、单类文件、上方中文说明位置、核心导入边界、正式数据/曲谱边界与必要回归；命名含义和注释质量人工审阅；验证七音组合、音区、未完成/非法/未匹配输入、有界前缀与清理、事件序号及静音可玩。
- `--staged`：只读真实索引blob，拒绝冲突和不允许路径，不执行索引代码；无Git仓库时报不适用，不自动init。
- `--check-package`：从明确正式快照构建，在无制作目录的临时环境安装、启动与验证关键操作。
- Git范围检查同步维护精确允许集合；本作不安装其他项目hook，不设置全局core.hooksPath。
- 已实现区域结构检查：清单引用与文件ID一致、逐区资源完整、跨区目标／落脚／条件校验、当前布局唯一来源、默认装载不依赖制作目录。实际工作区和非空索引blob的文件结构、package-data及Git资源例外由工具核验；专属逻辑归属、是否重复通用机制及灰盒是否沿用正式核心继续人工审阅，未实现检查明确写未覆盖。

注释是否准确、分包/职责/继承是否合理、许可及文件正文用途人工审阅。检查失败修正原因，不强制添加、不跳过hook、不降低要求。统一入口已实现，正式命令和实际结果见[验收记录](../technical/verification.md)；独立demo位于support/production/scenes/keyboard_demo，只供七音试听，排除默认测试、Git和发行，也不包含原作/正式游戏旋律触发。历史文档核对不能声称正式规范检查、游戏测试或CI通过。首次技术提交与GitHub推送已授权，仅覆盖审阅后的技术集合；不授权本机内容上传或产品发布。
